# Обзор проекта OneSTools.EventLog

## 1. Общее описание
Проект представляет собой набор инструментов для высокопроизводительного чтения и экспорта журнала регистрации 1С (старый формат, файлы `.lgf` и `.lgp`) в современные аналитические хранилища данных: **ClickHouse** и **ElasticSearch**.

Основная цель — обеспечить "live" (в реальном времени) или разовую выгрузку логов 1С для дальнейшего анализа, мониторинга и хранения.

## 2. Архитектура
Решение построено на модульной архитектуре, разделяющей ответственность между чтением, обработкой и сохранением данных.

### Основные слои:
1.  **Data Source (Источник данных)**: Файловая система с логами 1С (`.lgf` - метаданные, `.lgp` - данные).
2.  **Reader (Чтение)**: Библиотека `OneSTools.EventLog` отвечает за парсинг файлов логов. Поддерживает отслеживание появления новых файлов и изменений в текущем файле.
3.  **Exporter Core (Ядро экспорта)**: Библиотека `OneSTools.EventLog.Exporter.Core` реализует конвейер (pipeline) обработки данных с использованием **TPL Dataflow**. Это позволяет гибко управлять потреблением ресурсов и параллелизмом.
4.  **Storage (Хранилище)**: Абстракция `IEventLogStorage` позволяет сохранять данные в различные системы (ClickHouse, ElasticSearch).
5.  **Services (Службы)**:
    *   `EventLogExporter`: Служба для экспорта логов одной конкретной информационной базы.
    *   `EventLogExportersManager`: Служба-оркестратор, которая следит за каталогами кластера 1С, автоматически обнаруживает новые базы и запускает для них процессы экспорта.

## 3. Компоненты проекта

### 3.1. OneSTools.EventLog
Библиотека низкоуровневого чтения логов.
*   **`EventLogReader`**: Главный класс-фасад. Управляет чтением последовательности файлов `.lgp`. В режиме `LiveMode` использует `FileSystemWatcher` для ожидания новых данных.
*   **`LgfReader`**: Читает файл метаданных `1Cv8.lgf` (пользователи, компьютеры, события, метаданные и т.д.).
*   **`LgpReader`**: Читает файлы данных `YYYYMMDDxxxxxx.lgp`.
*   **`EventLogItem`**: Модель данных события лога.

### 3.2. OneSTools.EventLog.Exporter.Core
Ядро логики экспорта.
*   **`EventLogExporter`**: Класс, связывающий чтение и запись.
    *   Использует `BatchBlock` для накопления пачек событий.
    *   Использует `ActionBlock` для асинхронной записи пачек в хранилище.
    *   Управляет позицией чтения (resume capability) — запоминает последний обработанный файл и смещение.
*   **`IEventLogStorage`**: Интерфейс для реализации хранилищ.
    *   `WriteEventLogDataAsync`: Запись пачки событий.
    *   `ReadEventLogPositionAsync`: Чтение последней сохраненной позиции.

### 3.3. OneSTools.EventLog.Exporter (Service)
Исполняемое приложение (Console/Service) для экспорта одной базы.
*   Читает настройки из `appsettings.json`.
*   Запускает `EventLogExporter`.

### 3.4. OneSTools.EventLog.Exporter.Manager (Service)
Менеджер экспортеров для автоматизации работы с множеством баз.
*   **`ExportersManager`**: Основной сервис.
*   **`ClstWatcher`**: Следит за файлом `1CV8Clst.lst` (или структурой каталогов) для обнаружения баз.
*   Автоматически запускает и останавливает задачи экспорта (`EventLogExporter`) для каждой найденной базы.
*   Формирует имена баз данных/индексов на основе шаблонов.

## 4. Ключевые алгоритмы и процессы

### Процесс чтения (EventLogReader)
1.  Инициализируется с папкой логов.
2.  Читает `1Cv8.lgf` для кэширования метаданных.
3.  Определяет текущий файл `.lgp` (по позиции или дате).
4.  Читает события последовательно.
5.  Если файл закончился:
    *   Ищет следующий файл по времени изменения.
    *   Если следующего файла нет и включен `LiveMode`, ждет события от файловой системы.

### Пайплайн экспорта (EventLogExporter)
1.  **Source**: `EventLogReader` выдает `EventLogItem`.
2.  **Buffer**: `BatchBlock` накапливает события в пачки (размер `Portion`).
3.  **Sink**: `ActionBlock` получает пачку и вызывает `_storage.WriteEventLogDataAsync`.
4.  **Checkpoint**: Позиция чтения сохраняется в хранилище (обычно вместе с данными или отдельным запросом, зависит от реализации Storage). При перезапуске чтение продолжается с последнего сохраненного события.

### Управление базами (Manager)
1.  Сканирует указанные папки кластера (`reg_XXXX`).
2.  Фильтрует базы по маске имени.
3.  Для каждой подходящей базы проверяет наличие логов старого формата.
4.  Запускает отдельный "поток" (Task) с экземпляром `EventLogExporter`.
5.  При удалении базы останавливает соответствующий экспортер.

## 5. Конфигурация (appsettings.json)

Файл конфигурации разделен на секции:
*   **`Manager`**: Настройки поиска баз (пути к кластерам, шаблоны имен).
*   **`Exporter`**: Общие настройки (размер порции, таймауты, часовой пояс, параллелизм).
*   **`ClickHouse`**: Строка подключения и режим хранения (БД на базу или Таблица на базу).
*   **`ElasticSearch`**: Узлы кластера, настройки индексов (шаблоны, ротация по времени).

## 6. Рекомендации по доработке и развитию
*   **Мониторинг**: Добавить метрики (Prometheus) для отслеживания скорости чтения/записи, лага отставания и ошибок.
*   **Отказоустойчивость**: Улучшить обработку временных сбоев сети или БД (сейчас есть базовые ретраи, но можно сделать Circuit Breaker).
*   **Поддержка нового формата**: Архитектура позволяет добавить `SqliteReader` для чтения логов нового формата (SQLite), реализовав интерфейс, аналогичный текущему ридеру.
